## Implementation Plan: `Secret` Type for Storing Sensitive Values

### Analog
The closest analog for the serde pattern is `ContextRecordType` in `zbobr-api/src/task.rs` (enum with tagged variants). The config field type change follows the same pattern as `Model` / `Tool` fields — a custom type used in config structs generated by `#[config_struct]`.

---

### Overview

Introduce a `Secret` enum with two variants: `Value(String)` (literal secret) and `Env(String)` (environment variable name). TOML representation: `{ value = "..." }` or `{ env = "VAR_NAME" }`. Plain strings are no longer accepted. Apply to all 4 token fields in the codebase.

---

### Step 1 — Define `Secret` in `zbobr-api`

Add a new `Secret` enum to `zbobr-api` (which already has serde):
- `Secret::Value(String)` — stores a literal secret string
- `Secret::Env(String)` — stores an env var name; resolved at usage time
- `Default` → `Secret::Value(String::new())`
- TOML deserialization via serde: `{ value = "..." }` or `{ env = "..." }` (internally-tagged or a custom deserializer that reads a table with exactly one key)
- `Secret::resolve(&self) -> anyhow::Result<String>`: returns the value for `Value`, reads the env var for `Env` (error if unset)
- Derive `Clone`; no `Copy` (contains `String`)

---

### Step 2 — Migrate token fields in 4 config structs

Change field type from `String` to `Secret` in:
1. `ZbobrDispatcherConfig::agent_github_token` (`zbobr-api/src/config.rs`)
2. `ZbobrRepoBackendGithubConfig::github_token` (`zbobr-repo-backend-github/src/config.rs`)
3. `ZbobrTaskBackendGithubConfig::github_token` (`zbobr-task-backend-github/src/config.rs`)
4. `ZbobrExecutorCopilotConfig::copilot_github_token` (`zbobr-executor-copilot/src/config.rs`)

For each:
- Change type from `String` to `Secret`
- Remove `#[arg(long, env = "...")]` attribute (clap cannot parse `Secret` from a CLI string); add `#[config(skip_args)]` so the macro treats it as TOML-only
- Update `Default` impls:
  - `agent_github_token`: `Secret::Value("not-configured".into())`
  - Others: `Secret::Value(String::new())`

The `#[config_struct]` macro generates `*Toml` structs with `Option<T>` wrapping — `Option<Secret>` works fine since `Secret` implements `Deserialize`.

---

### Step 3 — Update copilot executor `build()`

The current copilot `build()` manually chains env vars (`COPILOT_GITHUB_TOKEN → GH_TOKEN → GITHUB_TOKEN`). With `Secret`, this logic is moved into the TOML config: user specifies `{ env = "COPILOT_GITHUB_TOKEN" }`. Remove the manual env var override chain in `build()` — simply use `merged.copilot_github_token.unwrap_or(defaults.copilot_github_token)` like other fields.

---

### Step 4 — Update call sites in dispatcher

In `zbobr-dispatcher/src/lib.rs`, `copilot_github_token()` returns `&str` from a `String` field. With `Secret`, it must return a resolved value:
- Change the method to return `anyhow::Result<String>` and call `self.copilot.config.copilot_github_token.resolve()`

In `zbobr-dispatcher/src/cli.rs` (`execute_tool` function):
- `let agent_token = &zbobr.config().agent_github_token` — call `.resolve()?` to get a `String`, propagate errors
- `copilot_github_token()` call — adapt to new `Result<String>` return

---

### Step 5 — Update validation methods

In `validate()` in `zbobr-repo-backend-github` and `zbobr-task-backend-github`:
- Replace `self.github_token.is_empty()` check with `self.github_token.resolve()?` and check if the resolved string is empty
- Error messages can stay the same

---

### Step 6 — Update `init.rs` template

In `zbobr/src/init.rs`, the generated sample TOML currently writes:
```
agent_github_token = "not-configured"
```
Change to:
```
agent_github_token = { value = "not-configured" }
```

---

### Step 7 — Update tests

In `zbobr-dispatcher/src/config.rs` tests:
- `ZbobrDispatcherToml` constructions use `agent_github_token: Some("toml-agent-token".into())` — change to `Some(Secret::Value("toml-agent-token".into()))`
- Assertions comparing `config.agent_github_token` as a string — call `.resolve().unwrap()` or compare the `Secret` value directly

Also update the commented-out tests in `zbobr-executor-copilot/src/config.rs` for the new field type (or remove them if they no longer apply).

---

### Key decisions
- `Secret` lives in `zbobr-api` (already has serde, already a dep of all affected crates)
- Token fields become TOML-only (no CLI args) — `#[config(skip_args)]`
- `resolve()` errors on missing env var (explicit contract: if you use `Env` variant, the var must be set)
- No backward compatibility: plain string TOML values for token keys will cause a deserialization error
