In zbobr-api/src/config.rs, remove the `!self.tools.is_empty() &&` guard from the global tool name check in validate(). The condition should simply be `!self.tools.contains_key(self.tool.as_str())`, always requiring the global tool to be resolvable. This ensures startup validation catches configs where [tools] is empty or doesn't contain the configured dispatcher.tool. Update existing tests if any test an empty-tools config that should now fail validation.
