## Review Fix: Default workflow roles now have explicit tools

### Problem
The review found that the new role-tool validation (requiring every role to have a `tool`) made the default workflow generated by `zbobr init` invalid. Six roles (`worker`, `test_planner`, `test_worker`, `reviewer`, `tester`, `merger`) used `..Default::default()` which left `tool` as `None`.

### Changes

**`zbobr/src/init.rs`** — Assigned explicit `tool` to each predefined role in `default_workflow()`:
- `worker` → `"smart"`
- `test_planner` → `"planner"`
- `test_worker` → `"smart"`
- `reviewer` → `"smart"`
- `tester` → `"smart"`
- `merger` → `"silly"`

These match the tool definitions already present in `default_config_toml()` (`smart`, `planner`, `silly`).

**`zbobr-api/src/config.rs`** — Updated `resolve_tool_name` doc comment from "Precedence: stage.tool → role.tool → global dispatcher.tool" to "Precedence: stage.tool → role.tool" since the global fallback was removed.

### Verification
All tests compile and pass (250+ tests across all crates, 0 failures).
